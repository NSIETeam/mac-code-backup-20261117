让 Workbuddy 参与项目协作

读取项目简介、任务节点与实际源码，获取开发说明，并把进展、评论和回复写回同一张协作表。

连接一次，按项目授权

  1. 在项目协作平台登录，点击右上角「Workbuddy 接入」。
  2. 选择一个或多个项目、只读或协作权限，生成授权。
  3. 在 Workbuddy 的自定义连接器中粘贴平台生成的 MCP 配置；或者使用下方接入包中的配置、凭证表单和 Skill。
  4. 让 Workbuddy 先调用 siyue_context、siyue_projects，确认授权范围后开始工作。

授权最长8小时，也会随当前工作台会话失效，可随时撤销。令牌放在连接器凭证配置中，不要发到聊天或提交到仓库。项目外的数据不会开放；成员被移除或账号停用后访问失效。

项目与代码如何对应

项目简介说明目标；协作表记录任务、负责人和时间节点；代码库显示原型作者、源码和真实检查记录。开发任务使用 task/<任务UUID> 分支，真实提交自动关联到任务。错题打印小程序的各模块为独立子仓库，主仓库固定各模块版本。

Git提交仍使用老师本人的可撤销 Git 凭证。MCP授权只用于平台信息和进展，不代替Git凭证。原型作者与实验室负责团队分别保留，不因后续开发而覆盖。

工具与边界

  • siyue_context / siyue_projects：身份、授权范围与项目列表。
  • siyue_project：项目、任务、节点及最近300条评论。
  • siyue_development：仓库、原型署名、修改申请、测试与发布记录。
  • siyue_build_log：读取指定提交的真实检查日志，定位失败原因。
  • siyue_code：目录和UTF-8源码文件，单文件上限512KB。
  • siyue_task_brief：任务分支、验收标准、测试命令。
  • siyue_record_action / siyue_comment：记录节点、评论与回复，需要协作授权。

节点完成、代码提交、负责人验收、管理员上线是不同状态。Agent不能管理成员、验收或发布；提交后自动检查，通过后可在代码库中点击「体验此提交」；合并后更新共享测试版本。失败时查看检查日志，修改后再次提交。正式发布仍须负责人验收具体版本，再由管理员操作。

401：重新授权；403：检查项目和操作范围；409：刷新记录后核对；413/415：文件过大或不支持在线文本查看。平台接入包不代表已在 Workbuddy 市场上架。
